# PhoSem — 노트북 사용 설명서

PIN 다이오드 die 이미지에서 미세 결함을 검출하는 MIL 기반 다중 라벨 분류 노트북입니다.

- 파일: `Phosem_ver2.ipynb`
- 실행 환경: Google Colab 

---

## 1. 실행 전 준비

### 런타임 설정

Colab 상단 메뉴에서 `런타임` → `런타임 유형 변경` → 하드웨어 가속기를 **T4 GPU**로 지정합니다.

> 노트북 메타데이터에 TPU가 지정되어 있으나 코드는 CUDA를 사용합니다. GPU로 바꾸지 않으면 셀 0에서 `CUDA: False`가 출력되고 학습이 CPU로 돌아 수 시간이 걸립니다.

### 데이터 위치

> **셀 1(파일 불러오기)은 사용하는 환경에 맞춰 반드시 수정해야 합니다.**
> 현재 코드는 작성자의 Google Drive 경로(`MyDrive/every_define/crop`)를 마운트해 로컬로 복사하는 방식으로 고정되어 있습니다. 아래 세 경우 모두 셀 1을 고쳐야 합니다.
>
> - **다른 Drive 경로를 쓰는 경우** — 셀 1의 `SRC` 값을 실제 폴더 경로로 바꿉니다.
> - **Colab에 직접 업로드하는 경우** — `drive.mount` 부분을 지우고, 업로드한 zip을 `/content/dataset`에 풀도록 바꿉니다. 예를 들어 왼쪽 파일 탭에 `data.zip`을 올린 뒤 `!unzip -q /content/data.zip -d /content/dataset` 한 줄로 대체하면 됩니다.
> - **로컬 Jupyter에서 실행하는 경우** — Drive 관련 코드를 전부 지우고 `DATA_DIR`만 이미지가 있는 폴더 경로로 지정하면 됩니다.
>
> 셀 2 이후는 `DATA_DIR` 하나만 참조하므로, **`DATA_DIR` 안에 아래 폴더 구조가 만들어지기만 하면 나머지 셀은 수정할 필요가 없습니다.**

Google Drive에 아래 구조로 이미지를 둡니다.

```
MyDrive/
└── every_define/
    └── crop/
        └── image.jpg
```

- 폴더명이 1순위 라벨입니다. 폴더로 못 찾으면 파일명(`1003-die-불-P.jpg`)에서 찾습니다.
- 파일명에 `die`가 들어간 이미지만 대상입니다 (`DIE_ONLY = True`).
- 경로가 다르면 셀 1이 `MyDrive` 전체에서 `every_define/crop`을 자동으로 찾습니다.

## 2. 실행 순서

| 단계 | 셀 | 내용 | 대략 소요 |
|---|---|---|---|
| 준비 | 0 → 1 | 라이브러리, 한글 폰트, 데이터 적재 (**셀 1은 환경에 맞춰 수정 필요**) | 2~5분 (첫 실행) |
| 데이터 | 2 → 3 → 4 | 라벨 파싱, 픽셀 환산, patch 유틸 | 30초 |
| 참고 | 5 → 6 → 7 | v2 구조 비교용 (건너뛰어도 무방) | 10초 |
| 핵심 | 8 → 9 → 10 → 11 | 3분할, MIL 모델, 지표 함수, 학습 | 학습 40~90분 |
| 결과 | 12 | 학습 곡선 3종 | 10초 |
| 평가 | 18 → 19 | val threshold 고정 후 test 보고, FP/FN 목록 | 5~10분 |

### 실행하지 않는 셀

**13, 14, 15, 16, 17, 20번은 실행하지 마십시오.**

이유는 아래 5장에 정리했습니다. `런타임 → 모두 실행`을 쓰면 이 셀들이 같이 돌아가면서 **학습되지 않은 모델의 잘못된 지표가 출력됩니다.** 반드시 셀을 하나씩 실행하십시오.

## 3. 핵심 파라미터

| 이름 | 값 | 위치 | 의미 |
|---|---|---|---|
| `PATCH` | 128 | 셀 4 | patch 한 변의 픽셀 수 |
| `STRIDE` | 64 | 셀 4 | 추론 시 슬라이딩 간격 |
| `ROI_C` | (300,230,556,486) | 셀 8 | 접합부 고정 영역 |
| `K_ROI` / `K_RAND` | 2 / 6 | 셀 8 | bag 하나를 이루는 ROI patch와 무작위 patch 수 |
| `MIN_SPLIT` | 5 | 셀 8 | 이보다 적은 클래스는 전량 학습에만 사용 |
| `MIN_REPORT` | 5 | 셀 8 | 이보다 적은 지표는 보고에서 제외 |
| `epochs` | 40 | 셀 11 | 학습 epoch 수 |
| `lr` | 1e-3 | 셀 11 | 학습률 |
| `batch_size` | 8 | 셀 11 | bag 단위 배치 |
| `patience` | 8 | 셀 11 | AP 기준 조기 종료 |

800×800 이미지 기준으로 추론 시 patch는 슬라이딩 144개에 ROI 4개를 더해 die 한 장당 148개입니다.

## 4. 출력 읽는 법

### 셀 8 — 분할 결과

```
train 1683  (양품 1312 / 불량 371)
val    521  (불량 79)   test  429  (불량 71)
빠른 검증 139장 | FP 보정계수 7.37
```

- 세 묶음에 같은 파일이 하나라도 겹치면 `분할 누수` assert가 걸립니다.
- val과 test는 현장 비율(불량 약 16%) 그대로입니다. 균형을 맞추지 않습니다.
- 빠른 검증은 양품을 60장만 써서 속도를 확보하고, 오검출 수에 보정계수를 곱해 전체 기준으로 환산합니다.

### 셀 11 — 학습 로그

```
epoch 12 | loss 0.4210 | thr 0.668 | recall 0.512 | precision 0.430 | F1 0.467 | AP 0.291 *
```

- 끝의 `*`는 그 epoch에서 AP가 최고를 갱신해 `best_mil.pth`로 저장됐다는 뜻입니다.
- **F1이 아니라 AP를 보십시오.** F1은 threshold에 따라 흔들리고, AP는 순위만 보므로 threshold와 무관합니다.
- AP 기저선은 불량 비율입니다. val 기준 약 0.15이므로, AP가 0.15 근처면 학습이 되지 않은 것입니다.

### 셀 18 — 최종 성능

```
[양/불]  test 429 die (불량 71) | thr 0.668  <- val에서 고정
  acc 0.816 | recall 0.465 [0.35, 0.58] | precision 0.446 [0.33, 0.56] | F1 0.455
  AP 0.405  (threshold 무관 지표)
  TP 33  FN 38  FP 41  TN 317
```

읽을 때 반드시 같이 봐야 하는 기준선이 두 개 있습니다.

- **정확도 기준선**: 전부 양품이라 답하면 358/429 = 0.834입니다. 현재 0.816은 그보다 낮습니다.
- **AP 기준선**: 불량 비율 71/429 = 0.166입니다. 현재 0.405는 그 2.44배입니다.

즉 순위를 매기는 능력에는 신호가 있고, threshold를 걸어 판정으로 바꾸는 단계에서 무너집니다.

원인별 표는 recall만 보면 안 됩니다. 셀 19의 오검출 분포와 같이 봐야 합니다. C와 B는 거의 모든 die에 발화하므로 recall이 1.00이어도 판별력이 없습니다.

### 셀 19 — FP / FN 목록

오검출 파일을 점수 내림차순으로 출력합니다. 점수가 높은 상위 몇 건은 **라벨 오류일 가능성이 있으므로 실제 이미지를 눈으로 확인**하는 용도입니다.

## 5. 알려진 문제

제출 시점에 남아 있는 항목입니다. 진단은 끝났고 다음 사이클에서 수정합니다.

### 5.1 v2 잔재 셀 (13~17)

셀 5에서 만든 `model`은 v2 구조이며 **이 노트북 안에서 학습되지 않습니다.** 셀 14, 15, 16은 이 학습되지 않은 `model`을 평가하므로 출력이 전부 무의미합니다. 저장된 출력에 `전체 acc 0.052`, `recall 0.000`이 보이는 것이 그 때문입니다. MIL 모델은 `model_ml`이고, 올바른 평가는 셀 18 하나뿐입니다.

셀 13은 학습 로그를 붙여넣어 그래프를 복원하는 개발용 도구입니다. 그대로 실행하면 `history_ml`이 빈 리스트로 덮어써집니다.

셀 17은 `n_good`과 `n_bad`를 val 기준으로 다시 계산해 **전역 변수를 덮어씁니다.** 이 상태에서 셀 11을 다시 돌리면 샘플러 크기가 잘못 잡힙니다.

### 5.2 셀 4의 옛 분할

셀 4에 이전 버전의 2분할 코드가 남아 있어 `va_items`를 한 번 정의합니다. 셀 8이 3분할로 다시 정의하므로 순서대로만 실행하면 문제가 없습니다. 다만 **셀 8 이후에 셀 4를 다시 실행하면 검증셋이 옛 분할로 되돌아갑니다.** 셀 4는 한 번만 실행하십시오.

### 5.3 pos_weight 이중 보정

셀 11의 `WeightedRandomSampler`가 이미 양품과 불량을 1대1로 맞추는데, 셀 8의 `pos_weight`가 전체 분포 기준으로 최대 20배까지 다시 가중을 겁니다. 같은 보정이 두 번 걸려 불량 쪽으로 과하게 쏠립니다.

바른 형태는 `n_bad / cnt`를 최대 5로 제한하는 것입니다.

### 5.4 학습량 부족

epoch당 약 90 step에 40 epoch이므로 총 3,600 step 수준입니다. 셀 12의 검증 AP 곡선이 추세 없이 진동하는 것이 그 증거이며, 이 상태에서 best epoch을 고르는 것은 사실상 제비뽑기입니다.

### 5.5 FOV 미확보

셀 3의 `FOV_UM`이 `None`이라 5µm가 몇 픽셀인지 확정되지 않았습니다. 촬영 시야값을 넣으면 즉시 산출됩니다. 값이 없는 동안은 후보 시나리오 표만 출력됩니다.

## 6. 자주 나오는 오류

| 증상 | 원인 | 조치 |
|---|---|---|
| `every_define/crop 폴더를 찾지 못함` | Drive 경로가 다름 | 셀 1의 `SRC`를 실제 경로로 수정 |
| `학습 가능한 클래스가 2개 미만` | 폴더명이 라벨 규칙과 다름 | 셀 2 출력의 미지정 파일 예시 확인 |
| `분할 누수` assert | 같은 파일이 두 묶음에 존재 | 데이터 폴더의 중복 파일 제거 |
| CUDA out of memory | 추론 배치가 큼 | 셀 10 `die_letter_scores`의 `batch`를 256으로 |
| 그래프 한글이 네모로 깨짐 | 폰트 적용 전 그래프 생성 | 셀 0 재실행 후 런타임 재시작 |
| 셀 12에서 unpack 오류 | 셀 13을 실행함 | 셀 11부터 다시 실행 |
